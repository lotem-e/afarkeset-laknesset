# Afarkeset LaKnesset - Claude Instructions

## What this is

A Hebrew RTL website that makes Knesset legislation accessible in plain
language. Lotem designed the full product in Figma ( "Knesset Frame 3" ); this
repo implements the MVP: agenda list, bill page, my-tracking, completed
legislation, and statistics. Full product details live in `PRD.md` ( English ).

## Content rules ( the project's first rule )

- Bill content was transcribed from Lotem's Figma design. The two fully written
  bills ( performers' rights, Basic Law: the Judiciary ) carry her editorial
  text - do not rewrite it, only fix transcription errors against the Figma.
- Political facts ( party seats, MK names / roles / factions, vote numbers ) are
  seed data and may contain errors - they are marked with comments for Lotem's
  verification. FLAG uncertainty, never present a guess as fact.
- Aggregate numbers ( "513 bills", stats bars ) are illustrative by design -
  they match the Figma, not reality, until a real API exists. They live only in
  `src/content/stats.ts`.
- Site content is Hebrew, plain language. Code, file names, comments, and docs
  are English.

## Stack and structure

Vite + React + TypeScript + Tailwind v4 + shadcn/ui ( base-nova ), Hebrew RTL
( `<html lang="he" dir="rtl">` ), font Heebo ( Google Fonts, weights 400/500/700 ),
react-router-dom.

- `src/content/` - ALL content as typed data, separate from components:
  `types.ts` ( the data model ), `stages.ts` ( the 5-stage pipeline meta ),
  `committees.ts`, `parties.ts`, `mks.ts`, `stats.ts` ( illustrative aggregates ),
  `bills/` ( `facts/` synced, `editorial/` hand-written, `merge.ts` joining
  them, plus the not-yet-migrated hand-written bills ).
- `design/` - the project's design memory: the Figma screens rendered to PNG,
  the design's full extracted text ( the source the Hebrew content was
  transcribed from ), and the render tool. See `design/README.md`. The Figma
  cloud file is the master; the local PDF export no longer exists.
- `scripts/` - the Knesset sync. `knesset-api.mjs` ( the OData client ),
  `knesset-maps.mjs` ( their vocabulary to ours ), `status-map.mjs` ( the ~40
  statuses to our 5 stages ), `sync-bill.mjs` ( writes a facts file ),
  plus the exploratory `spike-sync.mjs` and `measure-policy.mjs`.
  Full plan and open questions: `SYNC-PLAN.md`.

## Facts vs editorial ( the rule that protects the writing )

A synced bill has two halves that must never overwrite each other. **Facts** are
generated by `scripts/sync-bill.mjs` into `src/content/bills/facts/<billId>.ts`
and a human never edits them. **Editorial** lives in
`src/content/bills/editorial/` and a script never touches it. They join on the
Knesset's `BillID`. Facts win on matters of record, editorial wins on
presentation. Discussion content is keyed by the session's DATE, never by its
position, so a newly discovered session cannot shift a summary onto the wrong
day.

Editorial rules Lotem decided on 2026-08-04: a bill enters the site once it
clears its first real hurdle ( preliminary reading for private bills, first
reading for government and committee bills, which skip the preliminary ); and a
bill that leaves the pipeline stays on the site with an explanation rather than
disappearing. Sharpened 2026-08-12: "clears" requires evidence the bill moved
PAST the hurdle, so a bill rejected at its preliminary discussion never enters
( see SYNC-PLAN.md §3 ).
- `src/components/` - grouped one level: `ui/` ( shadcn ), `layout/`, `shared/`,
  `bills/`, `bill-page/`, `discussion/`, `filters/`, `stats/`.
- `src/pages/` - one file per route. Routes: `/`, `/bill/:id`,
  `/bill/:id/discussion/:n` ( n is 1-based across the whole bill, in the order
  `billDiscussions()` returns ), `/tracking`, `/completed`, `/stats`.
- `src/hooks/useTracking.tsx` - followed bills in localStorage
  ( key `knesset.trackedBillIds` ), exposed via React context.
- `styles/tokens/` - primitives → semantic → groups ( party colors ) →
  typography. Canon-compatible authoring ( same conventions as sample-project ).
- `Knesset-History/` - a nested, independent sub-app: Lotem's
  "הכנסת לדורותיה" landing page reviewing all 25 Knessets as hemicycle
  infographics. It has its own CLAUDE.md, package.json and dev server
  ( port 5186, `knesset-history` in the workspace launch registry ); only its
  sources are tracked here. Whether it becomes a page of this site is an open
  product decision.

## The legislation pipeline ( the data spine )

`preliminary → firstPrep → first → secondThirdPrep → secondThird`
( קריאה טרומית → הכנה לקריאה ראשונה → קריאה ראשונה → הכנה לקריאות שנייה
ושלישית → קריאות שנייה ושלישית ). Each bill has one `stages` array; the card
chips, bill-page accordions, and vote blocks all derive from it. Do not store
the same fact twice.

## RTL conventions

- Use logical utilities ( `ps-* / pe-* / ms-* / me-* / start-* / end-*` ), not
  physical left / right.
- Numbers, dates with slashes, and vote figures sit inside `dir="ltr"` spans so
  they read correctly inside Hebrew text.
- Arrow icons: "back" points RIGHT in RTL - pick lucide icons accordingly.

## Running it

`npm run dev` - port 5184 ( registered as `knesset` in the workspace
`.claude/launch.json` ). Build: `npm run build` ( runs `tsc` first; `noEmit`
is on, so no stray `.js` files next to `.tsx` ).

## Writing rule

No em-dashes anywhere - use a regular hyphen with spaces. Keep the PRD live:
update it with every meaningful change.
